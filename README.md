# PROJECT EXTREME++ — website

The official static site for **PROJECT EXTREME++ (BMW Edition)**, a custom Linux 4.19 kernel for the POCO F4 / Redmi K40S (`munch`).

Pure HTML, CSS and vanilla JavaScript. No framework, no bundler, no npm build step. GitHub Pages serves the files exactly as they are.

## What is included

- Animated hero, canvas telemetry backdrop and glass-panel UI
- Live latest-release panel powered by the public GitHub API
- Smart download matcher for HyperOS / AOSP and KowSU+SuSFS / clean KernelSU / No Root
- Live changelog built from GitHub releases, with verified static fallback entries
- Review wall fed by public GitHub issues titled `[Review] …`
- Review composer that opens a pre-filled GitHub issue
- Installation tabs, copy-to-clipboard verification commands, FAQ and community links
- Self-hosted fonts, PWA manifest, app icons and a small offline service worker
- Responsive layout, keyboard support and `prefers-reduced-motion` support

## Deploy on GitHub Pages

1. Create a new **public** GitHub repository, for example `extreme-kernel-site`.
2. Add these files to the repository root and push to the `main` branch.
3. In the repository, open **Settings → Pages → Build and deployment**.
4. Set **Source** to **GitHub Actions**.
5. The workflow in `.github/workflows/pages.yml` deploys automatically on every push to `main`.
6. Open the Pages URL shown by the workflow when it finishes.

All internal links are relative, so the site works at both:

- `https://<user>.github.io/` (user site)
- `https://<user>.github.io/<repo>/` (project site)

If your default branch is not `main`, update the branch name in `.github/workflows/pages.yml`.

### Local preview

```bash
cd extreme-kernel-site
python3 -m http.server 8080
```

Then open `http://localhost:8080`.

The service worker deliberately registers only on HTTPS, so local HTTP previews never get a stale offline cache. If you test the service worker locally, use a tunnel or a local HTTPS server.

## Configuration

Edit `assets/js/config.js`:

```js
window.EXTREME_CONFIG = Object.freeze({
  kernel: {
    owner: "PandeyJI-9",
    repo: "Extreme-PLUS-kernel-munch",
    fallbackBuild: "Build #133",
    releasesPerPage: 5
  },
  reviews: {
    owner: "PandeyJI-9",
    repo: "Extreme-PLUS-kernel-munch",
    titlePrefix: "[Review]",
    issuesPerPage: 50
  },
  // …
});
```

The important options:

| Option | Meaning |
| --- | --- |
| `kernel.owner` / `kernel.repo` | Repository whose latest release drives downloads and changelog |
| `kernel.fallbackBuild` | Build label shown before the live API answers |
| `kernel.releasesPerPage` | Number of releases used by the changelog |
| `companion.fallbackDownload` | EKM APK fallback link if the APK is not attached to a release |
| `reviews.owner` / `reviews.repo` | Repository whose issues are used as reviews |
| `reviews.titlePrefix` | Only issues whose title starts with this prefix appear |
| `links.*` | Telegram, developer, GitHub and changelog links |
| `cacheMinutes` | Browser cache lifetime for GitHub API responses |
| `requestTimeoutMs` | Maximum wait before the site falls back to cached data |

## How downloads are matched

The site requests the latest five releases, selects the newest non-draft, non-prerelease release, then matches attached `.zip` assets by filename:

| Choice | Filename tokens |
| --- | --- |
| HyperOS | `hyperos` |
| AOSP | `aosp` |
| KowSU + SuSFS | `susfs`, but **not** `nosusfs` |
| Clean KernelSU | `ksu` / `kernelsu` without `susfs` or `noroot` |
| No Root | `noroot` / `no-root` |

The EKM APK is resolved from any `.apk` asset in the same release. If GitHub is unavailable or rate-limited, the panel links directly to the releases page.

Keep variant filenames containing the room and root tokens above; otherwise a build will show “No exact match”.

## How reviews work

The review wall is **not** a fake testimonial carousel. It reads public issues from the configured review repository:

1. The issue title starts with `[Review]`.
2. The body contains the sections generated by the composer:

```md
### Review
Battery idle is excellent and the phone stays cool under Genshin.

### Rating
5 / 5

### ROM
HyperOS

### Root flavor
KowSU + SuSFS

### Build tested
Build #133
```

The site fetches the latest issues, filters out pull requests and non-review issues, and renders the rest newest-first. The **Write a review** button builds this exact issue body and opens GitHub with it pre-filled.

Two things to know:

- GitHub’s unauthenticated API allows 60 requests per hour per IP. The site caches responses in `localStorage` for 15 minutes to stay far below that.
- A newly posted review can take up to 15 minutes to appear, or you can force a refresh by clearing the site’s local storage/cache.

### Pinned reviews

If you want a permanent, curated review — or a fallback when GitHub is unreachable — add it to `assets/data/reviews.js`:

```js
window.EXTREME_REVIEWS = [
  {
    name: "Rider",
    username: "rider",
    rating: 5,
    review: "Battery idle and thermals are exactly what I wanted.",
    rom: "HyperOS",
    root: "KowSU + SuSFS",
    build: "Build #133",
    date: "2026-11-16",
    url: "https://github.com/PandeyJI-9/Extreme-PLUS-kernel-munch/issues/1"
  }
];
```

Curated reviews are merged with the live GitHub issues and de-duplicated by URL.

## Updating content for a new build

Most content updates itself from the GitHub release. The static HTML also contains fallback values for no-JavaScript visitors and search engines. When you cut a new build, update these if you want the fallback to stay current:

- `<strong data-latest-build>Build #133</strong>` and the release summary in `index.html`
- `kernel.fallbackBuild` in `assets/js/config.js`
- SoftwareApplication JSON-LD `softwareVersion`
- The fallback changelog entries (`FALLBACK_CHANGELOG`) in `assets/js/app.js`
- The static timeline in `#changelogList` (optional; live release notes replace it when the API answers)

Release notes support lightweight Markdown-style lines. The changelog renderer turns headings, bullets and common emphasis into readable items; it is not a full Markdown engine.

## Service worker and caching

`sw.js` pre-caches the shell, fonts, icons, CSS and JS. Navigations are network-first with an offline fallback; static assets are stale-while-revalidate.

After deploying changes, **bump `SW_VERSION` in `sw.js`** (for example `v1` → `v2`). That changes the service worker file, triggers an update, and replaces the old cache on the next visit. Without a bump, returning visitors may keep using the old cached CSS/JS until the browser revalidates.

GitHub API requests are cross-origin and intentionally never cached by the service worker. The app’s own `localStorage` cache is separate.

## Design system

- **Display type:** Anton
- **Body type:** Inter variable
- **Technical type:** JetBrains Mono variable
- **Palette:** carbon black, M-sport cyan `#3cdcff`, blue `#4678ff`, violet `#b06cff`, red `#ff3e63`
- **Effects:** glass panels, gradient text, scroll reveals, spotlight hover, hero tilt, particle canvas

All main tokens live at the top of `assets/css/style.css` under `:root`. Fonts are self-hosted in `assets/fonts/`; there are no third-party UI libraries or tracking scripts. All three font families are SIL Open Font License 1.1 — see `assets/fonts/LICENSE.txt`.

Animations are throttled and skip expensive canvas/tilt work on touch devices or when `prefers-reduced-motion: reduce` is set.

## Notes

- The GitHub API is public and unauthenticated. If the site is rate-limited, it shows cached data when possible and a direct releases link otherwise.
- Social previews currently use GitHub’s generated repository card. For a custom card, add an image and update the `og:image` / `twitter:image` URLs with an absolute deployment URL.
- The site is a front end for the kernel repository. Kernel source, releases, issues and the EKM app live in their own repositories.
